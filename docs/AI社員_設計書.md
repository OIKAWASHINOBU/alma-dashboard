### 1.2 共通の絶対規範（両スキル共通＝AI社員の人格規定）

1. **及川志伸の共鳴マーケティングが上位**。原田式は「下位互換ツール」として使う（判断を委ねてもらう構造設計／煽りと操作の拒否）
2. **創作禁止**：関係史・実測数値・逸話・ケーススタディ・実績を作らない。空欄は依頼者に返す
3. **使わない表現**：読者や第三者集団への毒舌（「貧乏」「バカ」系）、「洗脳されている」等の読者診断、検証不能な最上級の常用、演出としての心配クロージング、実在しない編集部名義、守れない一回性宣言、無条件の成果約束
4. **代替**：構造批判＋数式の突きつけ／構造を主語にする／検証可能な座標で語る
5. **合言葉**：「先輩受講生として書け。卒業生ヅラをするな」
6. **出力**：完成稿で納品、事実の空欄リストを別枠で添える

### 2.4 DBを使うときの回答ルール（AI社員が守る約束）

1. 数字には**パスと時点**（meta.version・各 as_of）を添える
2. データに無いことは「**未取得**」と答え、推測で埋めない。「照合不能」を0や「利用なし」に丸めない
3. 会員数・決済・入退会が食い違うときは **Shopify（決済）を正**とする
4. 率を出すときは**分母を書く**
5. DBは読むだけ。更新は `request_update`
6. **会員個人の情報は壁打ちの中だけ**で使い、外部に出す文章には書かない

```
  └ 設定          … 開始日・終了日・目標CPA・      └ /{ad_id}?fields=creative{…}
                    目標CV数・総予算・1日予算・          画像・タイトル・本文・CTA
                    配信期間・経過日数
              │                                  │
              └──────── update_dashboard.py ─────┘
                         ・広告名＝UTAGE登録経路名で突合
                         ・判定ロジック（§4.3）
                         ・集計・総合評価・次アクション生成
                                   │
                                data.json ──▶ index.html
```

- 認証：環境変数 `META_ACCESS_TOKEN`（GitHub Secrets から注入する想定）
- 広告アカウントID・スプレッドシートIDはスクリプト内に定数で記載

### 4.3 広告判定ロジック（`judge()`）

上から順に評価し、最初に当てはまったものを採用。

| 判定 | 条件 | 次アクション |
|---|---|---|
| データ不足 | 消化 < 100円 または LP到達 < 10 | 配信開始・消化量を増やす |
| 寄せる | CV ≥ 1 かつ CPA ≤ 目標CPA かつ 登録率 ≥ 3% | 予算を増やして拡大 |
| 継続 | CV ≥ 1 かつ CPA ≤ 目標CPA × 1.5 | 現状維持 |
| 要改善 | CTR ≥ 5% かつ CV = 0 | LP・フォームを見直す |
| 停止候補 | 消化 ≥ 1,000円 かつ CV = 0 | 停止または訴求の大幅変更 |
| 停止候補 | 消化 ≥ 500円 かつ CV = 0 かつ CTR < 3% | 同上 |
| 様子見 | 上記以外 | データを蓄積 |

LP判定：登録率 ≥ 10% →「勝ち」／LP到達 < 10 →「データ不足」／それ以外→「並」

### 4.4 総合評価ロジック

| 評価 | 条件 |
|---|---|
| データ不足 | 広告CPAが算出不能（広告CV 0） |
| 良好 | CPA ≤ 目標 かつ CV進捗 ≥ 30% かつ 広告CV > 0 |
| 注意 | CPA ≤ 目標 × 1.5 かつ 広告CV > 0 |
| 改善必要 | それ以外 |

そのほか：CV着地予測＝合計CV ÷ 経過日数 × 配信期間、予算消化率、広告／ハウスのCV貢献度、ファネル（インプレッション→クリック→LP到達→申込完了）を算出。

## 7. データ・情報の取り扱いルール（まとめ）

1. 事実・数値・関係史・逸話は**創作しない**（スキル規範／DB規範の両方）
2. 無いデータは「未取得」「照合不能」と明示し、丸めない
3. 数値の食い違いは Shopify を正とする
4. 会員個人の情報は外部向け文章に書かない
5. UTAGEの配信・削除・送信、GitHubのPR作成など外部に影響する操作は事前確認
6. 認証情報（Metaトークン等）はリポジトリに書かず Secrets で管理
