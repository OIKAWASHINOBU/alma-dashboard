# 画像・インフォグラフィックの作り方

## 誰が何を作るか
| 作るもの | 担当 | 道具 |
|---|---|---|
| LPのコーディング（HTML/CSS/動き） | Codex | `kit/`・`brief.md` |
| 画像（FVの背景・イメージ写真・区切りの挿絵・バナー・広告画像） | **GPTの最新画像生成モデル** | `scripts/gen_image.py` |
| インフォグラフィック（図解・比較・流れ・年表・数字の見せ方） | **GPTの最新画像生成モデル**（絵の部分）＋ HTML（文字と数字） | 下の「文字の扱い」参照 |
| 実在の人物・会場・受賞・商品の写真 | **生成しない**。受領した実物の写真を使う | — |

## モデルの選び方（毎回、最新を確かめる）
「最新」は入れ替わる。**画像を作る前に、OpenAI公式の画像生成ガイドで今の最新モデル名を確かめる**:
https://developers.openai.com/api/docs/guides/image-generation

2026-10-02 時点（上記ガイドで確認）:
| モデル | 使いどころ |
|---|---|
| `gpt-image-2.5-sunburst` | 本番の画像。最も高性能で、部分修正（編集）の精度が高い |
| `gpt-image-2.5-flare` | 下書き・案出し。速くて高品質 |

新しいモデルが出ていたら、この表を書き換えてから使う。`gen_image.py` は `--model` で指定する（既定値も書き換える）。

## サイズと品質（上記ガイドの仕様）
- 推奨: `1024x1024`（正方形）/ `1536x1024`（横）/ `1024x1536`（縦）
- 自由なサイズも可: 幅と高さは16の倍数、縦横比は1:3〜3:1、辺は3840px以下、総画素は655,360〜8,294,400
- 品質: `low`（下書き）→ 本番は `high` / `xhigh` / `max` を比べて決める
- 透過背景: `background: transparent` ＋ png か webp

LPでの目安:
| 用途 | サイズ | 品質 |
|---|---|---|
| FVの背景（スマホ） | 1024x1536 | high以上 |
| FVの背景（PC） | 1536x864（16:9） | high以上 |
| 区切りの挿絵・イメージ | 1536x1024 | high |
| インフォグラフィック（スマホで読む縦長） | 1024x1536 | xhigh |
| Meta広告（正方形 / 縦） | 1024x1024 / 1024x1280 | high以上 |
| 案出し（3〜4案） | 1024x1024 | low |

## 文字の扱い（いちばん大事）
公式ガイドの「制限」に、**文字の正確な配置と鮮明さは苦手なことがある**、**レイアウトが決まった構図で要素を正確に置くのは難しいことがある**と書かれている。だから:

1. **原稿の文言・数字・注記は、画像の中に描かせない。** HTML（kit）で重ねる。画像は「文字の無い絵」として作る
2. インフォグラフィックは「絵（アイコン・矢印・背景・イラスト）」をモデルで作り、**数字と文字はHTML/SVGでCodexが載せる**
3. どうしても画像の中に文字が要る時（広告画像など）:
   - 原稿の文言をそのまま、短く（1枚に見出し1つまで）
   - 生成後に**一文字ずつ原稿と照合**する（`copy_check.py` は画像を読めない）
   - 数字（例: 6.5倍・366社）と注記は、出典つきの原稿どおりか確かめる。注記が載らないなら、その数字は画像に入れない
4. 名義（神田先生・企業名義など）のトーンに合わない絵柄にしない（_skill-common §2）

## 作ってはいけないもの
- 実在の人物（講師・お客様・著名人）の顔や姿を生成すること。写真が無ければ仮置きにして受領を待つ
- 「お客様の声」「受賞」「会場」「実績」を、本物に見える生成画像で表すこと（捏造になる）
- 他社のロゴ・商標・参照LPの画像に似せること
- 医療・収入などの効果を誇張して見せる絵

## 流れ
1. ブロック対応表で「画像が要るブロック」を決める（`brief.md` の画像欄）
2. `templates/image-brief.md` で1枚ずつ指示を書く（目的・サイズ・入れない文字・トーン）
3. 案出し: `flare` × `low` で3〜4案 → 及川に選んでもらう
4. 本番: 選んだ案を `sunburst` × `high` 以上で作り直す。直しは編集（部分修正）で
5. `img/` に置き、`images.md` に記録（ファイル名・モデル・サイズ・品質・プロンプト・作成日）。`gen_image.py` が自動で追記する
6. 検品: 文字が入っていないか（入れた場合は一字照合）、人物・実績を偽装していないか、スマホ幅で主役が切れないか

## APIキー
`OPENAI_API_KEY` が必要。キーは案件フォルダやリポジトリに書かない（環境変数で渡す）。
